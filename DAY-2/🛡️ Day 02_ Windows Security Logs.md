# 🔐 Important Windows Security Event IDs

| Event ID | Meaning | SOC Relevance |
|---|---|---|
| **4624** | Successful Logon | Detect unusual account access |
| **4625** | Failed Logon | Investigate authentication failures |
| **4740** | Account Lockout | Investigate repeated failed attempts |
| **4732** | Member added to local security-enabled group | Detect potential privilege changes |
| **4672** | Special privileges assigned to new logon | Investigate privileged access |

### Quick Reference

```text
4624 → Login SUCCESS
4625 → Login FAILED
4740 → Account LOCKED
4732 → GROUP CHANGE
4672 → SPECIAL PRIVILEGES
```

> Event IDs should always be investigated with additional context. A single event does not automatically indicate malicious activity.

# 🧪 Lab: Detecting a Failed Windows Login

## Environment

**Operating System:** Windows 10/11

### Tools

- Windows Event Viewer
- PowerShell
- Administrator access

---

# Step 1: Create a Test User

Open **PowerShell as Administrator**.

Create a temporary test account:

```powershell
net user haxuser1 TestPassword123 /add
```

Verify that the account was created:

```powershell
net user haxuser1
```

---

# Step 2: Generate a Failed Authentication

Intentionally provide an incorrect password:

```powershell
net use \\127.0.0.1\IPC$ /user:haxuser1 WrongPassword
```

The incorrect credentials should generate a failed authentication event.

> This lab intentionally generates a failed login against your own Windows system.

---

# Step 3: Open Windows Security Logs

Open:

```text
eventvwr.msc
```

Navigate to:

```text
Windows Logs
→ Security
```

Filter the log for:

```text
Event ID: 4625
```

Locate the event generated by the failed authentication attempt.

---

# 🔍 Step 4: Analyze Event ID 4625

Open the event and examine the available fields.

Important fields include:

```text
Account Name
Account Domain
Logon Type
Failure Reason
Workstation Name
Source Network Address
Timestamp
```

The exact fields available can vary depending on the Windows version and authentication mechanism.

# 🕵️ SOC Investigation

Use the **5W investigation model**:

### WHO?

Which account was targeted?

### WHAT?

What type of authentication failure occurred?

### WHEN?

When did the event happen?

### WHERE?

What host or source address generated the attempt?

### WHY?

Why did the authentication fail?

# 🚨 Real SOC Scenario: Possible Brute Force

Imagine a SOC analyst observes:

```text
10:01  4625  admin  10.0.0.25
10:02  4625  admin  10.0.0.25
10:03  4625  admin  10.0.0.25
10:04  4625  admin  10.0.0.25
10:05  4625  admin  10.0.0.25
...
10:10  4625  admin  10.0.0.25
```

Repeated authentication failures targeting the same account from the same source could indicate a **brute-force or password-guessing attempt**.

Now imagine the sequence continues:

```text
4625
  ↓
4625
  ↓
4625
  ↓
4625
  ↓
4624
```

The successful login after numerous failures increases the priority of the investigation.

The analyst should investigate:

- Whether the source IP is expected
- Which account was accessed
- Logon type
- Authentication method
- What happened after the successful login
- Whether additional hosts were accessed
- Whether privileged activity followed

# 🧠 Detection Logic

A useful mental model is:

```text
Single 4625
     ↓
Usually low concern
     ↓
Check context

Multiple 4625 events
     ↓
Potentially suspicious
     ↓
Investigate source + target

Multiple 4625
     ↓
4624 Successful Logon
     ↓
Higher-priority investigation
     ↓
Correlate additional events
```

The key principle is:

> **Context + correlation = better detection**

# 📊 Example Analysis

### Observed Event

```text
Event ID: 4625
Account: haxuser1
Source: 127.0.0.1
Activity: Failed authentication
Reason: Invalid credentials
```

### Initial Assessment

The event represents a failed authentication attempt against the test account.

Because the activity was intentionally generated during this lab and originated from the local system, the event is **expected test activity**, not a security incident.

However, repeated failures against a real account from an unexpected external source would require further investigation.

---

# 🚨 What Would Make It More Suspicious?

A single failed login:

```text
4625
```

is generally weak evidence.

The following pattern is more concerning:

```text
Multiple 4625 events
        ↓
Same target account
        ↓
Same unexpected source
        ↓
Short time period
        ↓
4624 successful login
        ↓
Suspicious activity after login
```

This type of correlation provides much stronger evidence for potential credential attacks.

# 💡 Key Lesson

> **One failed login is an event. A pattern of failures followed by successful access can become a detection.**

A SOC Analyst should not immediately label every 4625 event as malicious.

Instead, investigate the:

**frequency + account + source + timing + logon type + surrounding events**

to determine whether the activity is actually suspicious.
